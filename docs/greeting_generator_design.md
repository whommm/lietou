# 智能打招呼文本生成器设计文档

## 1. 功能概述

在现有批量匹配功能基础上，新增一个独立的"打招呼文本生成"标签页，用于调用LLM API根据岗位信息自动生成标准化的猎头打招呼消息。

## 2. 核心需求

### 2.1 消息格式规范
```
您好，我是猎头顾问，目前有个base[城市]的[岗位名称]机会，
[岗位简单介绍，2-3句话]，
薪资可谈，
方便的话能发一份您的简历看看吗？
```

**格式要求：**
- 城市精确到市级（如"深圳"），不要区县街道（如不要"深圳南山区"）
- 岗位介绍简洁，2-3句话概括核心职责和要求
- 薪资统一写"薪资可谈"，不出现具体数字范围
- 结尾礼貌索要简历

### 2.2 输入信息
- 岗位名称
- 工作城市（需要从详细地址中提取市级）
- 岗位描述/JD（用于生成岗位简介）
- 薪资范围（仅用于理解，输出时替换为"薪资可谈"）

### 2.3 输出格式
- 生成的打招呼文本
- 可一键复制
- 可批量生成多个变体

## 4. 技术架构

### 4.1 服务层
**GreetingTextGenerationService**
- 接收岗位信息
- 构建Prompt调用LLM API
- 返回格式化后的打招呼文本

**Prompt设计：**
```
你是一个资深猎头顾问，擅长撰写简洁专业的候选人打招呼消息。

请根据以下岗位信息，生成一段打招呼文本：

岗位名称：{job_title}
工作城市：{city}
岗位描述：{job_description}
薪资范围：{salary_range}

要求：
1. 开头："您好，我是猎头顾问，目前有个base{city}的{job_title}机会，"
2. 中间：用2-3句话简洁介绍岗位核心职责和亮点（基于岗位描述提炼）
3. 薪资：统一写"薪资可谈"，不要出现具体数字
4. 结尾：礼貌索要简历，如"方便的话能发一份您的简历看看吗？"
5. 总字数控制在80-120字
6. 语气专业、友好、有吸引力

只输出打招呼文本，不要其他内容。
```

### 4.2 UI层
**GreetingGeneratorWidget**
- 岗位选择下拉框（复用现有岗位历史记录）
- 岗位信息预览卡片
- 生成结果文本框
- 操作按钮（生成、复制、批量生成）

## 5. 城市提取逻辑

### 5.1 提取规则
输入："深圳市南山区科技园"
输出："深圳"

实现方式：
- 使用中国城市列表匹配
- 优先匹配直辖市、地级市
- 去掉"市"、"区"、"县"等后缀
- 保留"北京、上海、天津、重庆"等直辖市原名

## 6. 数据流

```
用户选择岗位
    ↓
系统加载岗位信息（名称、城市、JD、薪资）
    ↓
点击"生成打招呼文本"
    ↓
构建Prompt → 调用LLM API
    ↓
LLM返回原始文本
    ↓
后处理（确保格式符合规范）
    ↓
展示在文本框中
    ↓
用户可复制或重新生成
```

## 7. 批量生成模式

### 7.1 功能
- 一次生成5个不同版本的打招呼文本
- 每个版本侧重点不同：
  1. 突出岗位亮点
  2. 突出公司优势
  3. 突出职业发展
  4. 突出工作生活平衡
  5. 通用版本

### 7.2 UI展示
- 使用标签页或列表展示5个版本
- 每个版本可单独复制
- 可选择"应用到自动打招呼"作为默认消息

## 8. 与自动打招呼功能的关联

### 8.1 数据共享
- 生成的打招呼文本可保存为默认模板
- 自动打招呼功能可读取此模板
- 支持在自动打招呼时动态替换变量（{job_title}、{city}）

### 8.2 配置项
- 在"打招呼生成"标签页生成的文本自动保存到配置
- 自动打招呼任务优先使用用户自定义模板
- 如未生成，则使用系统默认模板

## 9. 异常处理

### 9.1 错误场景
- LLM API调用失败：显示错误提示，可重试
- 岗位信息不完整：提示用户补充
- 城市提取失败：默认使用"该城市"

### 9.2 降级策略
- API超时：使用本地模板生成基础版本
- 无岗位信息：提供手动输入框

## 11. Prompt示例

**输入：**
- 岗位：高级产品经理
- 城市：深圳市南山区
- JD：负责电商平台产品规划，需要5年以上经验，熟悉电商业务流程
- 薪资：25-35k

**输出示例：**
```
您好，我是猎头顾问，目前有个base深圳的电商平台高级产品经理机会，
负责核心业务的产品规划与落地，团队氛围好且发展空间大，
薪资可谈，
方便的话能发一份您的简历看看吗？
```

## 12. 注意事项

1. **隐私合规**：不要在打招呼中透露客户公司具体名称（除非客户授权）
2. **频率控制**：生成文本仅用于辅助，实际发送需遵守平台规则
3. **个性化**：虽然是模板化生成，但应保留一定个性化空间
4. **城市精度**：严格确保城市只到市级，避免泄露过多位置信息
5. **薪资处理**：绝对禁止在输出中出现具体薪资数字，统一替换为"薪资可谈"
