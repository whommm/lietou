软件设计文档：智能岗位分析与寻访助手 (单机版)1. 项目概述本程序是一个面向猎头顾问的桌面端辅助工具。旨在通过调用大语言模型（LLM）API，将非标准化、晦涩的原始岗位描述（JD）自动转化为结构化的行业背景知识、核心准入门槛，以及直接可用于招聘平台的布尔搜索公式（Boolean Search）。2. 技术选型与架构程序采用本地客户端运行、云端大模型处理的轻量化架构。开发语言： Python 3.x图形界面（GUI）： CustomTkinter （提供现代化的UI外观，支持深色/浅色模式切换）网络与大模型交互： openai Python 官方库（主流国产模型如通义千问、DeepSeek 均兼容 OpenAI 接口规范，调用最稳定）本地配置存储： json 模块（用于保存 API Key 等用户设置）程序打包： PyInstaller （将 Python 脚本及其依赖打包为单一的 .exe 可执行文件）3. 界面布局设计 (UI Design)程序界面规划为三个主要区域：顶部配置区、左侧输入区、右侧输出区。3.1 顶部配置区用于设置和保存调用大模型所需的鉴权信息。API Base URL 输入框： 用于填写大模型服务商的接口地址（例如：https://api.deepseek.com/v1）。API Key 输入框： 密码本形式，输入时显示星号，保护密钥安全。保存配置 按钮： 点击后，将 URL 和 Key 写入本地 config.json 文件。程序下次启动时自动读取填充。3.2 左侧输入区用户操作的主阵地。JD 输入文本框： 大型多行文本框，带滚动条。用于粘贴招聘方发来的原始岗位信息。开始分析 按钮： 核心交互按钮。3.3 右侧输出区结果展示与提取区域。分析结果只读文本框： 大型多行文本框，带滚动条，设为只读状态（防止用户误删结果）。用于接收并展示大模型返回的内容。一键复制 按钮： 点击后，将右侧文本框内的所有内容复制到系统剪贴板。4. 核心工作与控制流程为确保软件在使用过程中不出现“卡死”现象，核心流程必须引入多线程（Threading）机制。触发与校验： 用户点击“开始分析”。程序首先检查 API Key 是否已填写，JD 文本框是否有内容。若缺失，弹出警告窗口拦截。UI 锁定： 将“开始分析”按钮状态置为 disabled（不可点击），文字改为“AI 正在思考中...”。后台处理（独立线程）：程序在后台新建一个工作线程。将“内置系统提示词”与“JD 文本”进行拼接。发起网络请求至 LLM API。结果回传与 UI 恢复：后台线程收到完整结果后，将文本发送回主界面，展示在右侧输出区。恢复“开始分析”按钮为 normal（可点击）状态，文字恢复为“开始分析”。5. 核心模块：内置系统提示词 (Master Prompt)这是整个程序的“大脑控制逻辑”。在代码中，这部分将作为一个常量字符串写死在程序内部。程序在向大模型发送请求时，会将此段文本作为 System Prompt 或拼接在用户 JD 之前。--- 提示词文本开始     "api_base_url": "[https://api.deepseek.com/v1](https://api.deepseek.com/v1)",
    "api_key": "sk-xxxxxxxxx..."
}
7. 异常处理机制 (Error Handling)必须在代码中捕获以下常见错误，并以弹窗形式告知用户，避免程序崩溃闪退：网络连接失败： 提示“无法连接到大模型服务器，请检查网络或 API 地址是否正确。”API Key 无效或欠费： 捕获 AuthenticationError 或 InsufficientQuota 异常，提示“API 密钥无效或账户余额不足。”超时 (Timeout)： 设置请求超时时间（如 60 秒），若超时则提示“分析耗时过长，请稍后重试。”
